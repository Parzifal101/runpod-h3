# runpod-h3

Генерация видео со звуком моделью **MiniMax H3** на арендованной GPU в RunPod через [WanGP](https://github.com/deepbeepmeep/Wan2GP). Одна команда ставит всё, запускает веб-интерфейс, перезапускает его при падениях и следит за памятью.

Проверено 2026-11-02: RTX 5090, WanGP v19.02, torch 2.10 / CUDA 13.

| Модель в WanGP | Ролик | Время | Цена ($1.19/ч) |
|---|---|---|---|
| H3 FL2VA Pruned 20B · PDD 8-Step | 5 с, 1280×704 | 1 мин 43 с | $0.034 |
| H3 FL2VA 33B · PDD 8-Step | 5 с, 1280×704 | ~1 мин 55 с | ~$0.038 |
| H3 FL2VA 33B · PDD 8-Step | 10 с, 1280×704 | 4 мин 48 с | $0.095 |

Для сравнения, тот же 5-секундный ролик через API: fal H3 Max Turbo $0.14–0.20, MiniMax H3-Lite $0.20, Higgsfield ~€0.33.

## Пошаговая инструкция

### Шаг 0. Один раз: аккаунт и баланс

1. Зарегистрироваться на [runpod.io](https://www.runpod.io) и включить двухфакторную аутентификацию (Settings → Security).
2. **Billing → Add credits**: пополнить баланс. На первую сессию хватит $5–10.

### Шаг 1. Выбрать хранилище: с volume или без

| | Без volume | С Network Volume |
|---|---|---|
| Что сохраняется после выключения | ничего, только скачанные ролики | окружение, модели, настройки |
| Первый запуск | ~15–20 мин | ~15–20 мин |
| Следующие запуски | снова ~15–20 мин (~$0.3) | ~2 мин |
| Стоимость в простое | $0 | ~$14/мес за 200 ГБ |

Volume окупается, если запускаете под чаще ~45 раз в месяц или не хотите каждый раз ждать.

**Если нужен volume (делается один раз):**
1. **Storage → Network Volumes → New Network Volume.**
2. Дата-центр: тот, где есть **RTX 5090**. Доступность видна при выборе.
3. Размер **200 ГБ** → Create.

### Шаг 2. Арендовать GPU (создать под)

1. **Pods → Deploy.**
2. Если есть volume, сверху выберите его в поле **Network Volume** (дата-центр подставится сам).
3. **Фильтр CUDA: 13.x.** На хостах с CUDA 12 наша сборка torch не запустится.
4. GPU: **RTX 5090** (~$1.19/ч), количество 1.
   - Почему не дешевле: L40, 4090 и RTX PRO 4500 дешевле за час, но медленнее, и ролик на них выходит дороже. RTX PRO 6000 (96 ГБ) имеет смысл только для 15-секундных роликов в высоком разрешении.
5. **Template:** RunPod PyTorch (любой, например `runpod/pytorch:...-cu1320-...`).
6. **Edit Template** (до запуска, потом редактирование сбрасывает под):
   - **Container Disk:** **200 ГБ** без volume или **30 ГБ** с volume;
   - **Expose HTTP Ports:** `8888, 7860`.
7. Instance pricing: **On-Demand** → **Deploy On-Demand**.
8. Подождать статус **Running**. Первая загрузка образа занимает 3–15 минут. Если прогресс в Logs стоит на месте больше 15 минут, сделайте Terminate и создайте под заново: он попадёт на другую машину.

### Шаг 3. Запустить (одна команда)

1. На странице пода: **Connect → Enable web terminal → Open Web Terminal.** Подойдёт и Jupyter Lab (порт 8888) → File → New → Terminal.
2. Вставить:

```bash
cd /workspace && git clone https://github.com/Parzifal101/runpod-h3.git && bash runpod-h3/start.sh
```

Скрипт поставит ffmpeg, Python 3.11, torch и зависимости WanGP (~5–10 мин) и напечатает ссылку:

```
WanGP is up:  https://<POD_ID>-7860.proxy.runpod.net
```

**Если под с volume и уже запускался**, достаточно:

```bash
bash /workspace/runpod-h3/start.sh --update
```

`--update` подтягивает свежие версии этого репозитория и WanGP. Без флага запускается то, что уже стоит.

### Шаг 4. Открыть интерфейс

Ссылка из терминала или **Connect → Port 7860 → HTTP Service**. Статус «Initializing…» в панели RunPod может висеть пару минут после фактического старта, на него можно не смотреть.

**Пароля на интерфейсе нет. Ссылку никому не давайте**: любой, у кого она есть, может генерировать на вашей GPU.

### Шаг 5. Сгенерировать первый ролик

1. Три выпадающих списка вверху:
   **MiniMax H3** → **FL2VA 33B** (лучше качество) или **FL2VA Pruned 20B** (меньше ОЗУ) → **PDD 8-Step**.
2. Режим: **Text Only** (только текст), **Start with Image** (первый кадр) или **End Image** (последний кадр).
3. **Category: 720p** → **Resolution: 1280x704 (16:9)** (или 9:16 для вертикали).
4. **Number of frames:** 124 = 5 с, 243 = 10 с (24 кадра = 1 с).
5. Промпт: каждый абзац, отделённый пустой строкой, становится **отдельным роликом в очереди**.
6. **Generate.**

**Первый запуск каждой модели скачивает её веса** (десятки ГБ, несколько минут). Время генерации меряйте со второго ролика.

Где смотреть ход генерации:
- в интерфейсе справа вверху: этап (Loading → Preparing Conditioning → Denoising N/8 → VAE Decoding) и время;
- в терминале: `bash /workspace/runpod-h3/start.sh --logs`. Тут видно всё, даже если вкладка закрыта. Ошибки начинаются с `Traceback`, готовый ролик — `Video file saved to Path`.

Выбор модели и параметры хранятся **во вкладке браузера**. После обновления страницы или автоперезапуска выставьте их заново.

### Шаг 6. Скачать ролики

```bash
bash /workspace/runpod-h3/start.sh --pack
```

Команда создаст `/workspace/h3-videos-<дата>.tar`. В Jupyter Lab (порт 8888) найдите файл в дереве слева → правый клик → **Download**. Отдельные ролики лежат в `/workspace/Wan2GP/outputs/`.

### Шаг 7. Выключить под

1. Скачать ролики (шаг 6). **Без volume всё на поде пропадёт.**
2. **Pods → ⋮ → Terminate.** Под без volume при Stop тоже ничего не стоит, но Terminate убирает его совсем.
3. Network Volume продолжает стоить ~$14 в месяц, пока вы его не удалите (Storage → Delete).

## Команды

| Команда | Что делает |
|---|---|
| `bash start.sh` | установить (если нужно) и запустить |
| `bash start.sh --status` | всё сразу: процесс, ссылка, GPU, ОЗУ, OOM-киллы, диск, число роликов, перезапуски |
| `bash start.sh --logs` | живой лог WanGP (Ctrl+C только закрывает просмотр) |
| `bash start.sh --pack` | упаковать ролики для скачивания |
| `bash start.sh --update` | обновить этот репозиторий и WanGP, затем запустить |
| `bash start.sh --stop` | остановить всё |

Логи: `/workspace/logs/wgp.log` (WanGP) и `/workspace/logs/restarts.log` (перезапуски).

## Что уже исправлено в скриптах

| Проблема | Симптом | Решение |
|---|---|---|
| WanGP отклоняет запросы через прокси RunPod | интерфейс открывается, но ничего не кликается (в консоли браузера 403 «Cross-origin request rejected») | `--public-url https://<POD_ID>-7860.proxy.runpod.net` |
| cuBLASLt на torch 2.10 + CUDA 13 | `CUBLAS_STATUS_NOT_INITIALIZED` на этапе «Preparing Conditioning» | `DISABLE_ADDMM_CUDA_LT=1 TORCH_BLAS_PREFER_CUBLASLT=0` |
| Утечка ОЗУ в WanGP (~1.3 ГБ на ролик) | через несколько часов процесс молча умирает (OOM kill), прокси показывает «Waiting for service to respond» | `supervisor.sh` поднимает WanGP через 5 с после падения; `mem_guard.sh` перезапускает его заранее, когда ОЗУ > 88 ГБ и GPU простаивает |
| uv ставит Python на стираемый container disk | после рестарта пода окружение на volume сломано | `UV_PYTHON_INSTALL_DIR=/workspace/.uv-python` |

После автоперезапуска обновите вкладку и выберите модель заново. Ролик, который генерировался в момент OOM, теряется.

## Если что-то не так

| Симптом | Что делать |
|---|---|
| Под долго в «Downloading your container» | ждать до 15 мин; дольше — Terminate и новый под |
| «Waiting for service to respond» | `bash start.sh --status`: если `WanGP: NOT running`, супервизор поднимет его за минуту; если `HTTP 000` дольше 5 мин — `bash start.sh` |
| Интерфейс не реагирует на клики | обновить вкладку (F5); проверить, что ссылка совпадает с той, что напечатал `start.sh` |
| Ошибка в генерации | `bash start.sh --logs` и найти строку `Traceback` |
| `OOM kills` в статусе растёт | меньше переключать модели за сессию; в `config.env` поставить `PROFILE=5` (меньше ОЗУ, медленнее) или `MEM_GUARD_GB` пониже |
| torch не стартует на хосте CUDA 12 | создать под с фильтром CUDA 13.x или в `config.env` раскомментировать вариант torch 2.8 + cu128 |

## Настройки: `config.env`

| Параметр | Значение |
|---|---|
| `WANGP_REF` | закрепить версию WanGP (commit или tag); пусто = последняя |
| `PROFILE` | 4 — проверенный; 5 — меньше ОЗУ, медленнее |
| `MEM_GUARD_GB` | порог ОЗУ для заранее сделанного перезапуска (лимит контейнера на 5090 ~99 ГБ) |
| `TORCH_SPEC` / `TORCH_INDEX` | версия torch; запасной вариант в комментарии |
| `ATTENTION`, `EXTRA_ARGS` | дополнительные флаги `wgp.py` |

## Советы по цене

- **Две сцены по 5 с дешевле одной на 10 с**: 10 с считается в ~2.8 раза дольше. Склейка через «Continue Video» в WanGP.
- **Одна модель за сессию**: переключение 20B ↔ 33B держит обе в ОЗУ и приближает OOM.
- **Готовьте промпты заранее и ставьте пачкой** (абзацы через пустую строку): простой GPU тоже оплачивается.
- Разрешение выше 720p заметно дороже. Дешевле апскейлить готовый ролик: в WanGP есть FlashVSR и SeedVR2 (Media Flow).
